# Technical Requirement Document (TRD)

## 1. System Architecture & Hardware Specifications
* Central Processing Unit: ESP32-S3 Microcontroller (Dual-core LX7, Wi-Fi + BLE, eFuse Vault).
* Power Input Subsystem: Standard 5V DC Laptop USB Port Connection.
* Audio Acquisition: Dual INMP441 I2S Digital MEMS Microphones.
* Vision Acquisition: ESP32-CAM Module with OV2640 Image Sensor and LED Ring Array.
* Environmental Sensors: DHT22 Capacitive Temperature & Humidity Sensor.
* Motion / Theft Sensing: MPU 6050 6-Axis Motion Tracking Module (Accelerometer + Gyroscope).

## 2. Multi-Model Database Schema Design

### 2.1 Model 1: HardwareBatchReport Schema
* `report_id` (UUID): Unique primary key for the hardware report.
* `batch_id` (String): Indexed identifier linking the report to a specific honey batch.
* `timestamp` (ISO 8601 DateTime): Time of hardware telemetry execution.
* `device_id` (String): Public address / ID of the originating ESP32-S3 unit.
* `signature` (String): ECDSA secp256k1 signature generated by software cryptographic key.
* `tinyml_predictions` (JSON):
  * `acoustic_state` (String): Output from FFT analysis (Baseline / Swarming / Queen Distress).
  * `varroa_infestation_rate` (Float): Percentage of detected mites from YOLOv8 vision model.
  * `brood_climate_score` (Float): Normalized thermal/humidity score from DHT22 readings.
  * `orientation_status` (String): MPU 6050 tilt/motion status.
* `tinyml_confidence` (Float): Overall confidence score of the hardware analysis.

### 2.2 Model 2: FarmerLabReport Schema
* `lab_report_id` (UUID): Unique primary key for the farmer-uploaded lab report.
* `batch_id` (String): Indexed identifier linking the lab report to a specific honey batch.
* `farmer_id` (String): User identifier of the uploading beekeeper/FPO.
* `upload_timestamp` (ISO 8601 DateTime): Upload time on the web platform.
* `document_uri` (String): Storage URI of the original uploaded lab PDF/Image.
* `lab_parameters` (JSON):
  * `moisture_content` (Float): Percentage moisture (FSSAI max 20.0%).
  * `hmf_content` (Float): mg/kg Hydroxymethylfurfural (FSSAI max 40.0 mg/kg).
  * `reducing_sugars` (Float): Apparent reducing sugar percentage (FSSAI min 65.0%).
  * `sucrose_content` (Float): Percentage sucrose (FSSAI max 5.0%).
  * `c3_c4_syrups` (Float): C3/C4 sugar percentage (FSSAI max 7.0%).
  * `smr_tmr_status` (Boolean): True if negative, False if positive for rice syrup.
  * `diastase_activity` (Float): Schade scale value (FSSAI min 8.0).
* `lab_accreditation_hash` (String): Cryptographic hash of the accredited testing facility certificate.

### 2.3 Model 3: FinalVerifiedReport Schema
* `final_report_id` (UUID): Unique primary key for the final consumer-facing report.
* `batch_id` (String): Indexed identifier mapping Model 1 and Model 2 together.
* `model1_ref_id` (UUID): Foreign key referencing Model 1 (`report_id`).
* `model2_ref_id` (UUID): Foreign key referencing Model 2 (`lab_report_id`).
* `synthesis_timestamp` (ISO 8601 DateTime): Timestamp of AI comparison execution.
* `ai_comparison_metrics` (JSON):
  * `data_consistency_score` (Float): Cross-validation score between hardware logs and lab metrics.
  * `purity_verdict` (String): Final quality decision (PASSED / FLAGGED / REJECTED).
  * `detected_discrepancies` (Array[String]): Discrepancies identified during dual-report evaluation.
* `summary_insights` (Text): Human-readable report summary synthesized for consumers.
* `qr_code_uri` (String): URI of the generated dynamic QR code image.
* `blockchain_tx_hash` (String): EVM transaction hash anchoring the report to the ERC-1155 token.

## 3. On-Device AI & Signal Processing
* Bio-Acoustics Engine:
  * Computes 128-point FFT on audio streams using ESP32-S3 DSP instructions.
  * Categorizes signals into: 100–220 Hz (Baseline), 250–450 Hz (Swarming), 340–500 Hz (Queen Piping).
* Time Difference of Arrival (TDOA) Localization:
  * Samples audio simultaneously across dual INMP441 mics separated by distance d.
  * Calculates time delay dt = t2 - t1.
  * Resolves spatial delta equation dr = vs * dt where vs = 343 m/s to output exact comb frame coordinate (#1 to #6).
* Vision Model: YOLOv8-nano TFLite model running on-device or via mobile app interface to detect Varroa destructor mites and Deformed Wing Virus (DWV).

## 4. Cryptographic Runtime & Storage Protocol
* Software Cryptography: Software-based ECDSA secp256k1 key generation and signature library executing within ESP32-S3 runtime with flash encryption enabled.
* Storage Buffer & Offline Sync Pipeline:
  1. Telemetry payload is formatted as a JSON string and signed via software ECDSA private key.
  2. Software checks active Wi-Fi connection.
  3. Active Connection: Payload posts directly to FastAPI cloud endpoint.
  4. Offline Connection: Payload is saved to local encrypted flash partition (SPIFFS/LittleFS/PouchDB).
  5. Reconnection Event: System streams buffered records to CouchDB cloud database.
  6. Garbage Collection: Automated background routine hard-deletes local records exceeding 7 days of age.
